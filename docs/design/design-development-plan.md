# Plan: the unified Design and Development spec

**Status:** proposed, then executed milestone by milestone. Input: `SERVERLESS_DESIGN_DEVELOPMENT_SPEC.md` v2.0 (kept in the maintainer's working tree, not in this repository), [CLAUDE.md](../../CLAUDE.md), and the code on `main`. It continues [serverless-plugins-plan.md](serverless-plugins-plan.md); the four items that plan left open are folded in here (§4, milestones L1-L4).

## 1. What exists, checked against the spec

The spec's inventory of 11 existing plugins is correct: all of them are on `main` (`aws-context`, `aws-ui`, `aws-guard`, `aws-explorer`, `aws-architect`, `aws-infrastructure`, `aws-security`, `aws-testing`, `aws-deploy`, `aws-cost`, `aws-observability`). The spec says to treat that as user-reported; the audit result is:

| Legacy capability the spec says to move                        | Present?                                                                                                      | Action                                                                                                                                                                        |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `aws-architect` diagrams (Mermaid)                             | **Yes**: `src/lib/diagram.ts`, `diagram` skill, CLI `diagram`                                                 | Move the engine to a shared package; `aws-diagrams` owns it; the architect `diagram` skill stays as a deprecated shim that runs the same code and points to the new owner     |

## 2. Decisions

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | **Shared code only through packages bundled at build time.** The diagram engine moves to `packages/architecture-graph`; the question engine for template evidence moves to `packages/template-analysis` rules or a new package when two plugins need it. Plugins never read each other's folders.                                                                                                                                                                                                                                                                                                                       |
| D2  | **Compatibility shims, not deletions.** Old commands keep working and print a one-line deprecation note naming the new owner. Duplicate internals are removed only in a later major version, after the new plugins have been released.                                                                                                                                                                                                                                                                                                                                                                                  |
| D3  | **First release of each Development plugin is local-first.** Each ships (a) deterministic analysis of the **declared** infrastructure in `cdk.out` templates for its services, (b) validators and designers for its domain (event patterns, ASL, OpenAPI, claims, cache behaviors, templates, flag schemas, and so on), (c) fixtures and a text/JSON report. Live AWS inspection through the SDK is **not** in 0.1; the capability matrix says `not yet implemented`. Reason: no real account is available (see the earlier plan, M4), and an SDK adapter that has only run against fakes is the weakest kind of claim. |
| D4  | **Mutation is out of every new plugin's 0.1.** Nothing invokes, publishes, sends, deletes, deploys, or starts a workload. Anything that would is a plan the user takes to `aws-deploy` or runs by hand.                                                                                                                                                                                                                                                                                                                                                                                                                 |
| D5  | **Result contract = the existing `report-contract`** (`AnalysisReport`, `Finding` with `confirmed                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | hypothesis | informational`, execution context, source label). The spec's `PluginResult`is a proposal; I adopt its`source` vocabulary (`local-code | aws-api | fixture | simulation | estimate`) as a field on new reports instead of creating a second envelope. |
| D6  | **Command count:** at most six skills per plugin; advanced controls are flags.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| D7  | **No scores.** Well-Architected output is evidence-backed findings and a backlog; there is no pillar score and no certification claim. Missing evidence is never compliant.                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| D8  | **Marketplace entries appear at release time**, not at merge (the repository's existing rule); "28 entries" is the end state after publishing, which the maintainer has not asked for. The implementation matrix tracks `implemented / tested / unverified`.                                                                                                                                                                                                                                                                                                                                                            |

## 5. Per-plugin release gate

Same as before: lint, typecheck, tests (negative cases included), `claude plugin validate`, packaging check in a throwaway worktree (installed from the plugin cache with only that plugin), README with permissions, charges, three examples, limitations, a capability matrix with honest status, a changeset, and evals for each agent.

## 6. Risks

- **Scope.** Seventeen plugins is more than one session. Each milestone is independently mergeable; the matrix always states what is done.
- **Unverified against AWS.** No milestone talks to a real account. Service semantics come from the AWS documentation and are checked against fixtures only; each README says so.
- **Spec drift.** Service limits and API fields change; every table that summarizes AWS guidance carries a source link and a snapshot date.
