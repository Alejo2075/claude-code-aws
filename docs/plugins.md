# Plugins

This page describes the serverless plugins in the repository. They are grouped by lifecycle category in the [main README](../README.md), which also links to each plugin's source folder. **Only `aws-context` and `aws-ui` are currently published in the marketplace**; the other plugins are still being developed and validated. Each plugin is designed to install on its own. Nothing here needs an account other than your own AWS account, and every plugin is read-only unless its README says otherwise.

```text
/plugin marketplace add Alejo2075/claude-code-aws
/plugin install <plugin>@claude-code-aws
```

| Plugin                 | What it does                                                                                                                                                                                                                                                                                                                  |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `aws-ai`               | Plan and review Amazon Bedrock applications locally: inspect Bedrock resources in synthesized CDK output, estimate token cost from prices you supply, chunk documents for retrieval, scan prompts for sensitive data, review RAG settings and agent tool permissions, and scaffold an evaluation harness. No model is called. |
| `aws-api`              | Inspect API Gateway APIs in synthesized CDK output, validate OpenAPI contracts, compare a contract with the declared routes, and prepare (never send) test requests with masked credentials. No request is made.                                                                                                              |
| `aws-architect`        | Turn requirements or an existing CDK app into architecture artifacts: Mermaid diagrams that separate declared from inferred links, a Well-Architected style review against the template, decision tables with sources, ADRs, and a plan other plugins can read.                                                               |
| `aws-auth`             | Inspect Cognito user pools and app clients in synthesized CDK output, check decoded token claims against what an API expects, and recommend sign-in flows by application type. Tokens are never read or printed; no user is created.                                                                                          |
| `aws-config`           | Validate AppConfig feature flag documents and JSON configuration against a schema, plan a gradual rollout from a deployment strategy, and inspect AppConfig and Parameter Store resources in synthesized CDK output. Nothing is deployed and no value is changed.                                                             |
| `aws-containers`       | Inspect ECS Fargate services, task definitions, and ECR repositories in synthesized CDK output, validate Fargate CPU and memory, review Dockerfiles, scaffold a hardened Dockerfile, and map stopped-task reasons to likely causes. No image is built, pushed, or run.                                                        |
| `aws-context`          | Verified AWS account, principal, region, and environment for the current project, with a status skill and a session-start check. Read-only: it never changes AWS resources.                                                                                                                                                   |
| `aws-cost`             | Estimate and compare the monthly cost of serverless workloads from stated inputs and dated AWS list prices, clearly separate from billed amounts. Makes no AWS calls.                                                                                                                                                         |
| `aws-database`         | Design DynamoDB key schemas from access patterns, plan queries and cost units, plan key-schema migrations, and inspect DynamoDB and Aurora definitions in synthesized CDK output. No rows are read or written.                                                                                                                |
| `aws-deploy`           | Plan and run CDK deployments safely: identity checked, templates hashed, destructive and permission-broadening changes acknowledged, production confirmed by name. Never deploys without an explicit plan.                                                                                                                    |
| `aws-diagrams`         | Generate, validate, update, and export architecture diagrams as editable Mermaid from CDK output, plans, or inventories, marking what is intended, declared, deployed, observed, or inferred.                                                                                                                                 |
| `aws-edge`             | Inspect CloudFront distributions in synthesized CDK output, lint CloudFront Function code against the runtime's restrictions, check Lambda@Edge constraints, review cache policies, and map HTTP status codes to likely causes. No distribution is changed and no invalidation is created.                                    |
| `aws-email`            | Inspect SES identities, configuration sets, and receipt rules in synthesized CDK output, validate email templates against sample data, dry-run a recipient list without sending, and judge bounce and complaint rates. No email is sent.                                                                                      |
| `aws-events`           | Inspect EventBridge buses, rules, targets, and Scheduler schedules in synthesized CDK output; try an event pattern against a sample event; check schedule expressions and their next run times across time zones. No AWS calls, no events published.                                                                          |
| `aws-explorer`         | Browse CloudFormation and CDK stacks, their resources, events, and resource properties in one AWS account and region, read-only.                                                                                                                                                                                              |
| `aws-guard`            | Asks for approval before AWS-changing commands, especially in production or with an unverified identity. A guardrail, not an enforcement boundary.                                                                                                                                                                            |
| `aws-infrastructure`   | Inspect, synthesize, diff, review, and scaffold CDK TypeScript serverless infrastructure from synthesized CloudFormation templates, without deploying anything.                                                                                                                                                               |
| `aws-lambda`           | Inspect Lambda functions in synthesized CDK output, scaffold TypeScript handlers with validation and idempotency hooks, check configuration against Lambda's quotas, and prepare (never run) an invocation command. No function is invoked.                                                                                   |
| `aws-messaging`        | Inspect SQS queues and SNS topics in synthesized CDK output, check dead-letter and FIFO design, try SNS filter policies against sample messages, and diagnose a backlog from numbers you supply. No messages are sent, received, or deleted.                                                                                  |
| `aws-observability`    | Read-only operational visibility for serverless apps: Lambda and queue health, bounded logs and metrics, alarms, and an evidence ledger for incident investigation. Never changes anything.                                                                                                                                   |
| `aws-prototyping`      | Plan, run locally, compare, and promote bounded serverless proof-of-concepts: a hypothesis, a success metric, a budget, a cleanup plan, and results labeled simulated or measured. Never deploys or runs a second rollout engine.                                                                                             |
| `aws-security`         | Audit CDK templates and, read-only, the account for security problems: IAM, public exposure, API authorization, secrets, with evidence. Advisory only.                                                                                                                                                                        |
| `aws-storage`          | Inspect S3 buckets and EFS file systems in synthesized CDK output, validate object keys, plan uploads (single or multipart) and lifecycle rules, and review bucket policies. No objects are read, written, or deleted.                                                                                                        |
| `aws-streaming`        | Inspect Kinesis Data Streams and Amazon Data Firehose in synthesized CDK output, size shards from throughput, check where partition keys land, and validate delivery buffering. No records are written or read.                                                                                                               |
| `aws-testing`          | Run, generate, and report tests for serverless apps: Lambda handlers, CDK assertions, and event fixtures for API Gateway, SQS, SNS, EventBridge, DynamoDB Streams, S3 and Step Functions. Never deploys.                                                                                                                      |
| `aws-ui`               | Shows the AWS user, region, and environment as labels in the prompt footer, read from the aws-context snapshot, with a warning only when something is wrong. Never calls AWS.                                                                                                                                                 |
| `aws-well-architected` | Review a serverless workload across the six Well-Architected pillars with the Serverless Lens in mind: separate verified evidence, self-reported answers, automated inferences, and missing evidence, and produce a prioritized improvement backlog. No scores and no certification.                                          |
| `aws-workflows`        | Validate Step Functions state machine definitions (Amazon States Language), read them out of synthesized CDK output, walk them logically against sample input, and summarize an execution history you supply. Nothing is started.                                                                                             |

See [implementation-matrix.md](implementation-matrix.md) for status and known gaps, [capabilities.md](capabilities.md) for what each plugin can and cannot do, and [plugin-ownership-migration.md](plugin-ownership-migration.md) for which plugin owns what.
